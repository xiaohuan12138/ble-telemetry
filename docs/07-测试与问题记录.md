# 第 7 章 测试与问题记录

## 7.1 单元测试

测试位于 `android/app/src/test/java/`，共 5 个测试类，全部针对**纯逻辑层**（`protocol/` 与 `domain/`），不依赖 Android 框架，可直接用 JUnit 跑。

| 测试类 | 被测对象 | 用例 |
|--------|---------|------|
| `Crc16Test` | `Crc16` | 已知向量校验、单比特翻转必被检出、空载荷、大端写入 |
| `FrameParserTest` | `FrameParser` | 整帧一次到、半帧分片到、一次两帧半、垃圾前缀、CRC 错只丢 1 字节、缓冲区溢出 |
| `KalmanFilterTest` | `KalmanFilter` | 首次测量直接采信、常值输入收敛、阶跃输入响应、增益单调收敛、reset 后状态清空 |
| `RuleEngineTest` | `RuleEngine` | 单次达标不触发、连续 N 次触发、冷却期内不重复、不满足清零、滞回死区 |
| `ReconnectPolicyTest` | `ReconnectPolicy` | 延迟指数增长、抖动在范围内、上限封顶、最大次数 |

运行：

```bash
./gradlew testDebugUnitTest
```

**为什么只测这两层**：BLE 与 UI 依赖 Android 框架，需要 Robolectric 或 instrumentation test，成本高、稳定性差。把 `protocol` 与 `domain` 设计成**不依赖 Android 的纯 Kotlin**，正是为了让核心算法可被低成本测试——这是分层设计带来的直接收益。

## 7.3 问题记录

### 7.3.1 编译环境问题

| # | 现象 | 根因 | 解决 |
|---|------|------|------|
| 1 | `The 'org.jetbrains.kotlin.android' plugin is no longer required for Kotlin support since AGP 9.0` | AGP 9.0 起内置 Kotlin 支持，不能再单独声明该插件 | 从 root 与 app 两处 `plugins {}` 删除该声明 |
| 2 | `kotlinOptions {}` 报未解析 | AGP 9 改用新的 Kotlin DSL | 改为 `kotlin { compilerOptions { jvmTarget = ...; freeCompilerArgs.add(...) } }` |
| 3 | `Minimum supported Gradle version is 9.6.0. Current version is 9.5.0` | AGP 9.5 与 Gradle 版本绑定 | 升级 Gradle 到 9.6.0 |
| 4 | Gradle 下载失败 `getaddrinfo ENOTFOUND services.gradle.org` | 官方源不可达 | 改用腾讯镜像 `https://mirrors.cloud.tencent.com/gradle/`（实测阿里云、清华源均 404） |
| 5 | `Error opening zip file ... gradle-instrumentation-agent-9.5.0.jar` | 本地 Gradle 缓存损坏 | 换用完整解压目录 |
| 6 | 本机仅有 `android-37` SDK | compileSdk 版本不匹配 | `compileSdk = 37` / `targetSdk = 37` |

### 7.3.2 Kotlin 编译错误

| # | 文件 | 错误 | 原因 | 修复 |
|---|------|------|------|------|
| 7 | `Frame.kt:123` | `Unresolved reference 'pow'` | Kotlin 新版移除 Float 版 `pow` | 改用 `java.lang.Math.pow`，入参转 `Double` |
| 8 | `SensorHubService.kt:208` | `first()` 只能 suspend 调用 | `dispatchAction` 是普通函数 | 改为 `private suspend fun` |
| 9 | `SensorHubService.kt:236` | `Unresolved reference 'cancel'` | 缺 import | 加 `import kotlinx.coroutines.cancel` |
| 10 | `DeviceDetailViewModel.kt:121,143` | `Unresolved reference 'first'` | 缺 import | 加 `import kotlinx.coroutines.flow.first` |

### 7.3.3 运行时问题

| # | 现象 | 根因 | 解决 |
|---|------|------|------|
| 11 | 启动即崩：`NullPointerException: Attempt to invoke interface method 'int java.lang.CharSequence.length()' at SwitchCompat.makeLayout` | 项目主题是 Material **2**（`Theme.MaterialComponents.DayNight`），但布局用了 Material **3** 的 `MaterialSwitch`，主题属性缺失导致 text 为 null | 全局替换 `com.google.android.material.materialswitch.MaterialSwitch` → `com.google.android.material.switchmaterial.SwitchMaterial`（M2 版本，视觉等价） |
| 12 | `adb: no devices/emulators found` | 模拟器未启动 | 启动 Pixel_7，等待约 55 秒开机完成 |
| 13 | `adb shell cat` 读 ui.xml 内容为空 | shell 输出编码/权限 | 改 `adb pull` 到本地再解析 |

### 7.3.4 硬件与固件问题（设计阶段规避）

| # | 现象 | 根因 | 解决 |
|---|------|------|------|
| 14 | BH1750 读数为 0 | 两个函数各自 `new BH1750()`，Wire 重复初始化 | 改文件级 `static BH1750 gLightMeter`，全局唯一实例 |
| 15 | 串口打印 MTU 数值异常 | 误用 `getConnectedCount()` 当连接句柄 | 改用 `getPeerDevices()[0]` |
| 16 | ESP32 `printf("%ulu", x)` 输出错乱 | `%ulu` 不是合法格式符，会错位读参 | 改 `%u` + `(unsigned int)` 强转 |
| 17 | 连上但收不到数据 | 只调了 `setCharacteristicNotification(true)`，未写 CCCD | 补第二步写 `ENABLE_NOTIFICATION_VALUE` |

## 7.4 已知局限

| 项 | 说明 | 改进方向 |
|----|------|----------|
| 小组件数据在进程死亡后丢失 | 用静态缓存而非 Room | 改用 `RemoteViewsService` + 异步查询 |
| 未做真实硬件联调 | 硬件已采购，尚未接线 | 接线后按 `00-手把手使用指南.md` 第五章排查 |
| 无配对加密 | 当前为开放连接 | 加 BLE Pairing / LE Secure Connections |
| 数据库无迁移代码 | version = 1，无历史包袱 | 加字段时补 `Migration` 对象 |
| 未做多设备并发压测 | 仅两台设备验证 | 增至 5+ 台观察连接稳定性 |
