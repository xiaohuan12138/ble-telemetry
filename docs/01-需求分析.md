# 第 1 章 需求分析

## 1.1 项目背景

低功耗蓝牙（BLE）是物联网设备与手机之间最常用的短距离通信方式。市面上大量温湿度计、手环、智能灯都采用 BLE 与手机配对。但在教学实践中，BLE 开发存在两个门槛：

1. **协议栈抽象层次多**：应用层要理解 GATT 的 Service / Characteristic / Descriptor 三层结构，还要处理异步回调与线程安全；
2. **调试依赖硬件**：没有下位机就无法验证通信逻辑，学习过程容易被硬件采购周期卡住。

本项目以 ESP32 为下位机、Android 手机为上位机，构建一个完整的"传感器数据采集 + 设备控制"闭环系统，并在设计中刻意加入**自定义二进制协议、断线重连、数据滤波、自动化规则**等工程化要素，使其超出"点灯 demo"的复杂度，达到课程 C 档（挑战级）要求。

## 1.3 功能性需求

| 编号 | 需求 | 说明 | 对应实现 |
|------|------|------|----------|
| F1 | BLE 设备扫描 | 扫描周边 BLE 广播，展示名称、MAC、RSSI、信号格数 | `BleScanner` + `DeviceListFragment` |
| F2 | 建立 GATT 连接 | 连接指定设备、发现服务、订阅 Notify | `BleConnection` |
| F3 | 实时数据展示 | 温湿度气压光照数值 + 实时滚动曲线 | `DeviceDetailFragment` + `RealtimeChartView` |
| F4 | 设备反向控制 | 手机下发指令控制 LED 亮度、蜂鸣器、采样周期 | `buildCommandFrame` + `CHAR_CTRL` |
| F5 | 历史数据存储 | 所有读数落库，可翻页查看 | Room `readings` 表 + `HistoryFragment` |
| F6 | 自动化规则 | 温度超阈值自动触发动作，含防抖与冷却 | `RuleEngine` + `RulesFragment` |
| F7 | 多设备管理 | 支持同时维护多个设备的连接与重连 | `BleConnectionManager` |
| F8 | 桌面小组件 | 无需打开 App 即可查看最新读数 | `SensorWidgetProvider` |

## 1.4 非功能性需求

| 编号 | 需求 | 指标 / 做法 |
|------|------|------------|
| N1 | 数据完整性 | 每帧带 CRC16 校验，错误帧直接丢弃并计数 |
| N2 | 连接鲁棒性 | 断线后指数退避自动重连，带随机抖动避免惊群 |
| N3 | 权限降级 | 蓝牙权限被拒 → 支持手动输入 MAC 直连；通知权限被拒 → 降级为 App 内横幅 |
| N4 | UI 状态完整性 | 每个数据界面都有加载态、空态、错误态三套视图 |
| N5 | 无硬件可演示 | 内置模拟数据源，生成**真实二进制帧**走同一解析器 |
| N6 | 资源可控 | WorkManager 定期裁剪数据库，避免无限增长 |

## 1.5 用户角色与场景

**角色**：单用户（个人物联网爱好者 / 课程学习者），不存在多用户与服务端。

**典型场景**：

1. 用户打开 App → 自动申请蓝牙与通知权限 → 进入设备列表
2. 点击扫描 → 列表出现 `SensorHub-01`、`SensorHub-02`
3. 点击某个设备 → 进入详情页 → 点击连接 → 曲线开始滚动
4. 在详情页拖动 LED 滑块 / 点击蜂鸣器按钮 → 下位机执行
5. 切到规则页 → 新建"温度 > 30℃ 触发蜂鸣" → 达标时自动执行
6. 切到历史页 → 查看已存读数，可清空
7. 回到桌面添加小组件 → 不打开 App 也能看到最新温度

## 1.6 运行环境

| 端 | 要求 |
|----|------|
| Android | minSdk 26（Android 8.0）/ targetSdk 37 / compileSdk 37 |
| 手机硬件 | 支持 BLE 的 Android 设备（BLE 权限在 Android 12+ 需显式申请） |
| 下位机 | ESP32-WROOM-32，Arduino Framework + NimBLE-Arduino |
| 传感器 | AHT20（温湿度）、BMP280（气压/温度）、BH1750（光照） |
| 执行器 | LED（PWM 调光）、有源蜂鸣器 |
| 开发工具 | Android Studio、PlatformIO |

## 1.7 课程最低复杂度标准对照

| 标准要求 | 本项目实现 | 位置 |
|----------|-----------|------|
| ≥4 个界面，含列表→详情 | 设备列表、设备详情、规则、历史、设置（5 个），列表→详情通过 Navigation 传参 | `ui/` 五个 Fragment |
| 数据持久化 | Room 三表 + DataStore 偏好 | `data/` |
| 一项硬能力 | BLE 通信（系统级 API，非三方 SDK） | `ble/` |
| 协程 + ViewModel | 全项目无裸线程，扫描/连接/入库全走协程；每个界面配 ViewModel | 全局 |
| 权限降级 | 三级降级（蓝牙 / 通知 / 硬件） | 见 3.6 |
| 自定义业务逻辑模块 | CRC16 协议帧、卡尔曼滤波、规则引擎、重连策略 | `protocol/` `domain/` |
| 加载 / 空 / 错误态 | `UiState` 密封接口统一驱动 | `ui/common/UiState.kt` |
