# 01 · 需求分析

## 1.1 项目定位

**PixelLab 像素工坊** —— 本地图像处理工作台。用户拍照或从相册选图，App 提供基于
**卷积算法** 的滤镜处理、几何变换（旋转/裁剪）、EXIF 元数据查看、灰度直方图统计、
ML Kit 离线文字识别，支持批量处理与结果分享。

- 主 App：《Android 移动终端应用开发技术》（2 学分）交付物
- 选题：**C1 智能图像处理（C 档 · 挑战级）**
- 伴生模块：**P4 分享/导出卡片**（1 学分主交付）+ **P1 桌面小组件**（加分项）
- 仓库：https://github.com/xiaohuan12138/pixellab

## 1.2 选题动机（微电子方向）

图像本质是**二维离散信号**：本项目核心的卷积滤镜（低通/高通/梯度算子）、
高斯模糊（可分离 FIR 级联）、灰度直方图（概率密度统计、μ/σ 指标），
全部是《信号与系统》《数字信号处理》的语言在二维图像上的直接应用。
选择 C1 的理由是把课程设计的内容与考研方向（集成电路/半导体物理）的思维
训练打通，而不是单纯完成一个 App。

## 1.3 最低复杂度标准逐条对照

| 指南要求 | 本项目实现 | 对应模块 |
|---|---|---|
| ≥4 界面，含"列表→详情" | 6 个界面：图库(列表) → 编辑(详情) + 相机 + 批量 + 统计 + 设置 | `ui/` |
| 数据持久化 | Room `photos` 表（处理历史）+ DataStore（偏好） | `data/` |
| 硬能力：设备能力 | **CameraX 相机拍照**（生命周期绑定、权限降级） | `ui/camera/` |
| 异步与生命周期 | 全协程：卷积跑 `Dispatchers.Default`，Flow + `repeatOnLifecycle(STARTED)` 收集，ViewModel 持 Bitmap 防旋转丢失 | `ui/editor/` |
| 权限申请与降级 | CAMERA 拒绝 → 降级 UI + 二次申请入口；相册走照片选择器**零权限**；无相机模拟器仍可安装（uses-feature required=false） | `ui/camera/`、`Manifest` |
| 自定义业务逻辑模块 | **卷积滤镜引擎**：通用 3×3 卷积 + 可分离高斯 + 边缘检测核族 + 直方图统计，纯手写无图像库 | `image/` |
| 加载/空/错态 UI | 图库空态、编辑处理中进度条、相机拒绝态、批量失败跳过计数 | 各 Fragment |

## 1.4 C1 强制技术点覆盖

| C1 要求 | 实现 |
|---|---|
| CameraX 滤镜/裁剪/旋转 | CameraX 1.4.2 拍照 → 编辑页滤镜应用 + 90° 旋转 + 1:1/4:3/16:9 居中裁剪 |
| 批量处理 | WorkManager `CoroutineWorker` 队列，多选 9 张整批套用，实时进度上报，单张失败不中断 |
| EXIF | `exifinterface` 读取拍摄时间/型号/焦距/光圈/ISO/方向；加载时按 orientation 自动转正 |
| ML Kit 识别 | `text-recognition-chinese`（bundled 离线模型，模拟器可用），结果存历史、可复制 |
| 图形渲染/性能优化 | 两次解码限尺寸（4000px 照片→48MB 内存压到 ~5MB）；getPixels 批量搬运替代逐像素 JNI；高斯可分离 O(N·2k)；直方图 View 屏宽分桶、onDraw 零分配 |

## 1.5 个性化差异（同题防抄袭，2 必做 + 1 自选）

1. **必做① 卷积滤镜引擎**：核可配置（5 组预设核 + 高斯 + 灰度），处理前/后对比 + 耗时量化。
2. **必做② 批量处理流水线**：WorkManager 后台队列 + 进度上报 + 失败跳过。
3. **自选③ 灰度直方图与 μ/σ 量化指标**：前/后对比直方图，把"效果"变成数字。

## 1.6 用户故事

- 作为学生，我想给实验报告截图加批注感（锐化/边缘），一键处理并保存历史。
- 作为用户，我想批量给多张照片套同一滤镜，退出页面也不中断。
- 作为用户，我想看到处理前后的直方图变化，理解滤镜到底做了什么。
- 作为用户，我想把处理结果生成带参数和学号水印的卡片分享出去。
- 作为重度用户，我想在桌面直接看到最近处理的图，一键回到 App。

## 1.7 非功能需求

- 离线可用：滤镜/识别/导出全部本地完成，不依赖网络。
- 性能：1280px 图卷积 ≤ 500ms（中端机）；列表滚动不卡（缩略图 ≤256px）。
- 可解释性：核心算法纯 Kotlin 手写 + 教学级注释，可逐行答辩。
