# 第 6 章 伴生模块设计（P1 桌面小组件）

## 6.1 选题说明

| 项目 | 内容 |
|------|------|
| 伴生模块编号 | **P1 桌面小组件** |
| 与主 App 的关系 | 共享同一套 BLE 数据链路与 Room 数据库，是主 App 的"只读视图延伸" |
| 独立价值 | 用户无需打开 App 即可看到最新读数，解决"看一眼温度要点 4 次屏幕"的痛点 |

**为什么选 P1 而不是其他伴生模块**：本项目主 App 的核心产出是"传感器读数"，桌面小组件是这些数据最自然的消费场景——小组件的本职就是"零点击获取关键信息"。二者契合度高，不是为做而做。

## 6.2 技术原理

### 6.2.1 RemoteViews 是什么

小组件运行在**桌面进程（Launcher）**，不在本 App 进程内。这意味着：

- ❌ 拿不到自己的 `View` 对象，不能 `findViewById`
- ❌ 不能用自定义 View、RecyclerView、ConstraintLayout
- ✅ 只能通过 `RemoteViews` "远程描述"界面，再交给桌面进程渲染
- ✅ 跨进程通信靠 `AppWidgetManager.updateAppWidget()`

`RemoteViews` 本质是一个**可序列化的界面操作指令集合**：

```kotlin
val views = RemoteViews(context.packageName, R.layout.widget_sensor)
views.setTextViewText(R.id.tvWidgetTemp, "26.5")     // 一条指令
views.setTextColor(R.id.tvWidgetTemp, color)          // 又一条指令
views.setOnClickPendingIntent(R.id.widgetRoot, pi)    // 点击指令
manager.updateAppWidget(appWidgetId, views)           // 打包发过去
```

### 6.2.2 RemoteViews 支持的控件（白名单）

| 支持 | 不支持 |
|------|--------|
| `TextView` `ImageView` `Button` | 自定义 View |
| `LinearLayout` `FrameLayout` `RelativeLayout` | `RecyclerView` |
| `AnalogClock` `Chronometer` | `ConstraintLayout`（Android 12 前） |
| `ListView` `GridView` `StackView`（需 `RemoteViewsService`） | `ViewPager` |

**因此本项目实时曲线无法放进小组件**——`RealtimeChartView` 是自定义 View。小组件只展示**三个数值文本 + 时间**，这是 RemoteViews 能力范围内的最优设计。

### 6.2.3 刷新策略

```xml
<!-- appwidget-provider 中配置 -->
android:updatePeriodMillis="1800000"   <!-- 系统最小 30 分钟 -->
```

**系统自动刷新最小间隔是 30 分钟**，对实时温湿度毫无意义。所以本项目采用**主动推送**：

```
SensorHubService 收到 BLE 数据帧
        │
        ▼
SensorWidgetProvider.updateWidgetData(context, data)
        │
        ▼
AppWidgetManager.updateAppWidget()  →  桌面进程刷新
```

这是小组件做实时数据的标准做法：把 `updatePeriodMillis` 设为 0（禁用系统刷新），改由数据侧驱动。

## 6.3 布局设计

```xml
<!-- res/layout/widget_sensor.xml -->
<LinearLayout android:id="@+id/widgetRoot" ...>
    <TextView  android:id="@+id/tvWidgetTitle" android:text="SensorHub" />
    <LinearLayout orientation="horizontal">
        <TextView android:id="@+id/tvWidgetTemp" />   <!-- 26.5 ℃ -->
        <TextView android:id="@+id/tvWidgetHum"  />   <!-- 58 % -->
        <TextView android:id="@+id/tvWidgetLux"  />   <!-- 320 lx -->
    </LinearLayout>
    <TextView  android:id="@+id/tvWidgetTime" />      <!-- 14:23:07 -->
</LinearLayout>
```

**空态处理**：数据为 `null` 时显示 `--` 与"暂无数据"，而非留白。小组件同样遵循加载/空态规范。

**状态着色**：温度 > 30℃ 时把数值染红（`setTextColor`），让用户在桌面一眼看出异常。这是 RemoteViews 少数支持的动态属性之一。

## 6.4 生命周期

| 回调 | 触发时机 | 本项目处理 |
|------|---------|-----------|
| `onUpdate` | 系统周期性刷新 / 小组件刚添加 | 从缓存 `lastData` 取最后一次数据渲染 |
| `onEnabled` | 第一个小组件添加到桌面 | 无需特殊处理 |
| `onDisabled` | 最后一个小组件被移除 | `lastData = null` 释放引用 |
| `onReceive` | 收到自定义广播 | 默认实现会分发到 `onUpdate` |

## 6.5 与小组件相关的 Android 版本差异

| 版本 | 差异 | 处理 |
|------|------|------|
| Android 12 (API 31) | `PendingIntent` 必须声明 `FLAG_IMMUTABLE` 或 `FLAG_MUTABLE` | 按 `Build.VERSION.SDK_INT` 分支 |
| Android 12 | 小组件圆角由系统自动裁剪 | 布局里不要自己画圆角 |
| Android 8.0 | 小组件预览图需用 `previewImage` 属性 | 已配置 |

## 6.6 明确的技术取舍（答辩需主动说明）

```kotlin
@Volatile
private var lastData: SensorData? = null   // 进程内静态缓存
```

**局限**：这是**进程内静态变量**，App 进程被系统回收后就没了，小组件会显示"暂无数据"，直到用户下次打开 App。

**更健壮的做法**：把最新读数存进 Room，小组件自己开协程查询。这样即使 App 进程死了，桌面仍能显示最后一次数据。

**为什么本项目用了静态缓存**：小组件的 `onUpdate` 运行在桌面进程主线程，**不允许做耗时操作**（包括数据库查询，可能触发 ANR）。要正确异步查询需要引入 `WorkManager` + `RemoteViewsService`，复杂度显著上升。在"演示完整性"与"工程完备性"之间，本项目选择了前者，并在此明确标注为已知局限。

> 答辩时主动说出这一点，比被问出来要好得多——它体现了你知道正确答案是什么，只是做了有理由的取舍。

## 6.7 配置文件清单

| 文件 | 作用 |
|------|------|
| `res/xml/sensor_widget_info.xml` | 小组件元数据（尺寸、预览图、刷新周期） |
| `res/layout/widget_sensor.xml` | 布局（仅 RemoteViews 白名单控件） |
| `widget/SensorWidgetProvider.kt` | 逻辑实现 |
| `AndroidManifest.xml` 中 `<receiver>` | 注册，需 `android.appwidget.action.APPWIDGET_UPDATE` intent-filter |

## 6.8 使用方式

1. 桌面长按空白处 → 小组件
2. 找到 SensorHub → 拖到桌面
3. 打开 App 并连接设备 → 小组件数值开始跳动
4. 点击小组件 → 直接打开 App 详情页
