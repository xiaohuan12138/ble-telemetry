## 8.3 技术亮点

1. **自定义二进制协议 + CRC16**：不用 JSON，20 字节一帧，适配 BLE MTU 限制；CRC 检出错误直接丢弃而非显示错误值。
2. **流式帧解析 + 滑动窗口**：出错只丢 1 字节而非清空缓冲区，最大限度抢救已收到的好数据。
3. **指数退避 + 随机抖动重连**：平衡快速恢复与省电，抖动避免多设备同时重连的惊群效应。
4. **卡尔曼滤波**：五公式标量实现，Q/R 参数有物理依据，增益自动收敛，可与滑动平均实时切换对比。
5. **三重防抖规则引擎**：连续命中 + 冷却 + 滞回，彻底解决阈值告警的误报与刷屏。
6. **双温度源交叉校验**：AHT20 与 BMP280 各能测温，互相对照，任一漂移可即时发现。
7. **模拟数据源走真实协议栈**：生成真实字节帧喂给同一解析器，无硬件也能验证全链路。
8. **纯自绘实时曲线**：环形缓冲 + Canvas，无第三方图表库。

## 8.4 个人收获

| 维度 | 收获 |
|------|------|
| 通信协议 | 理解了"为什么嵌入式不用 JSON"，学会设计带校验、带序号、带长度的帧格式 |
| 异步编程 | 掌握 `callbackFlow` 把 Java 回调包装成协程挂起函数，理解 `repeatOnLifecycle` 与 `launchWhenStarted` 的本质区别 |
| 架构 | 体会分层带来的可测试性——把纯逻辑隔离出来后，5 个测试类就能覆盖核心算法 |
| 可靠性工程 | 认识到"能跑"和"能在恶劣条件下稳定跑"是两回事，重连、校验、裁剪、降级都是为后者服务的 |
| 调试 | 掌握了从现象反推根因的方法：崩溃堆栈 → 源码行 → 属性缺失 → 主题与组件版本不匹配 |

## 8.5 后续改进方向

1. **真实硬件联调**：按 `00-手把手使用指南.md` 完成接线与烧录，用 nRF Connect 交叉验证协议。
2. **多设备并发压测**：现仅 2 台，拟增至 5 台，观察连接调度与信道竞争。
3. **安全加固**：引入 BLE Pairing（LE Secure Connections），防止陌生设备冒充。
4. **数据导出**：历史记录导出 CSV，便于后续分析。
5. **云端同步**：接入 MQTT，把数据推到 Home Assistant。
6. **小组件健壮性**：改用 `RemoteViewsService` 从 Room 异步查询，消除进程死亡后数据丢失的问题。

## 8.6 结语

本项目的价值不在于"做了一个能连蓝牙的 App"，而在于**把实验室 demo 与工程产品之间的那段距离走了多少**：带校验的协议、能自愈的连接、不误报的告警、优雅降级的权限处理、可裁剪的存储。这些不炫技，但决定了软件能否在真实环境中被信任。
