# SensorHub 手把手使用指南

> 面向"拿到一堆源码但不知道从哪下手"的情况。
> 每一步都写明：**点哪里 → 看到什么 → 算成功**。跟着做完一遍就通了。

---

## 零、先搞清楚这堆文件是什么关系

你不需要"融合"它们。它们天生就是一对：

| 在哪运行 | 文件夹 | 干什么 |
|---|---|---|
| **ESP32 开发板** | `firmware/` | 读传感器 → 打包成二进制帧 → 用蓝牙广播出去 |
| **你的安卓手机** | `android/` | 扫到蓝牙信号 → 连上 → 解包 → 显示曲线 → 反控 LED |

**唯一的连接点是蓝牙**，不需要接线、不需要网络、不需要配置 IP。
两边各自跑起来，手机会自动找到板子。

```
firmware/  ──烧录──▶  ESP32  ┈┈┈ 蓝牙 ┈┈┈▶  手机（装着 android/ 编译出来的 App）
```

**所以顺序是：先让手机端跑起来（不需要硬件），再搞硬件。**

## 二、第一步：让手机端跑起来（**今天就能做，硬件没到也能做**）

### 2.1 打开项目

1. 打开 Android Studio
2. 首屏点 **Open**（不是 New Project）
3. 选文件夹：`ble-sensorhub\android` ← **注意选 android 这一层，不是外层**
4. 点 OK

此时右下角会出现一个转圈的进度条，写着 **Gradle Sync**。这是它在下载依赖，**第一次要 5–15 分钟**，取决于网速。**别急，别关。**

### 2.2 Sync 完成后你会看到什么

左侧文件树变成这样（不再是空空的）：

```
app
 └─ java
     └─ com.sensorhub.app
         ├─ SensorHubApp.kt
         ├─ protocol/
         ├─ ble/
         ├─ ui/
         └─ ...
```

底部 Build 窗口最后一行是：

```
BUILD SUCCESSFUL in 3m 21s
```

**看到 BUILD SUCCESSFUL 就算这一步成功。**

### 2.3 连上你的手机

**用真机，不要用模拟器**（模拟器没有蓝牙）。

1. 手机 → 设置 → 关于手机 → 找到「版本号」→ **连点 7 下** → 提示"您已进入开发者模式"
2. 手机 → 设置 → 系统 → 开发者选项 → 打开 **USB 调试**
3. 用**能传数据的线**（不是那种只能充电的）连电脑
4. 手机弹出"是否允许 USB 调试"→ 勾"始终允许" → 确定
5. Android Studio 顶部工具栏的设备下拉框里会出现你的手机型号，**选它**

> 如果下拉框里没出现手机：换一根线 / 换 USB 口 / 手机上把"USB 用途"改成"传输文件"。

### 2.4 运行

点工具栏那个 **绿色三角 Run ▶**（或按 Shift+F10）。

第一次会编译 2–5 分钟。完成后：

- 手机上自动装上一个叫 **SensorHub** 的 App 并打开
- 底部有四个 tab：**设备 / 规则 / 历史 / 设置**

**App 打开了就算成功** ✅

### 2.5 打开模拟数据源（没有硬件时的关键一步）

1. 点底部 **设置**
2. 打开第一个开关 **「模拟数据源（无硬件演示用）」**
3. 弹出提示"已切换到模拟数据源"

### 2.6 现在逐个看界面（这就是你作业要演示的东西）

| 页面 | 你会看到什么 | 说明 |
|---|---|---|
| **设备** | 点「开始扫描」→ 出现 `SensorHub-01`、`SensorHub-02` 两条 | 这是假的，但列表→详情跳转是真的 |
| **设备**（点进任一条） | 四个数字（温度/湿度/气压/光照）开始跳动，下面**曲线在滚动** | 数据 1 秒刷新一次 |
| 详情页中间 | 「实时曲线」下面有 4 个单选：温度/湿度/气压/光照 | 点哪个画哪个 |
| 详情页下方 | **滤波方式**三个单选：原始 / 滑动平均 / 卡尔曼 | 切成"原始"曲线毛刺多，切"卡尔曼"变平滑——**这是答辩加分项** |
| 详情页下方 | LED 滑杆、鸣叫按钮、上报周期滑杆 | 没有硬件时点了没反应，但命令确实生成并发出了 |
| **规则** | 两条预置规则：高温告警、光线不足自动补光 | 可以开关、删除、新增 |
| **历史** | 一条条记录，带时间和"模拟/BLE"标记 | 数据真的写进了 Room 数据库 |
| **设置** | 模拟开关、自动重连、通知、手动 MAC | 都是 DataStore 持久化，杀掉 App 重开还在 |

**做到这里，你已经有一个能演示、能录屏的完整 App 了。** 硬件没到也不影响你先把文档、PPT、录屏做出来。

### 2.7 桌面小组件（伴生模块 P1）

手机的桌面 → **长按空白 → 小组件（或"窗口小工具"）** → 找到 **SensorHub** → 拖到桌面。
它显示最新温度/湿度/光照，几秒刷新一次。

## 三、第二步：给 ESP32 烧固件（硬件到了再做）

### 3.1 接线（照抄这张表）

把 ESP32 插在面包板上，然后：

| 从 ESP32 | 接到哪里 |
|---|---|
| **3V3** | 三个传感器模块的 VCC（**必须是 3V3，接 5V 会烧**） |
| **GND** | 三个模块的 GND |
| **GPIO21** | 三个模块的 **SDA / DA** |
| **GPIO22** | 三个模块的 **SCL / CL** |
| **GPIO2** | LED 正极（LED 负极串 220Ω 电阻到 GND） |
| **GPIO4** | 蜂鸣器的 I/O 脚 |

> 三个模块并联：VCC 都接 3V3、GND 都接 GND、SDA 三根拧一起接 GPIO21、SCL 三根拧一起接 GPIO22。
> 这叫 I2C 总线，靠"地址"区分（AHT20=0x38、BMP280=0x76、BH1750=0x23），不会打架。

### 3.2 烧录

**用 PlatformIO（推荐）：**

1. VS Code 装 PlatformIO 插件
2. 左侧点外星人图标 → **Open Project** → 选 `ble-sensorhub\firmware`
3. 底部状态栏点 **→（箭头，Upload）**
4. 第一次会自动下载库（约 2 分钟），然后自动编译上传

**用 Arduino IDE：**

1. 库管理器装 4 个库：`NimBLE-Arduino`、`Adafruit AHTX0`、`Adafruit BMP280 Library`、`BH1750`
2. 把 `include/` 的 5 个 `.h` 和 `src/` 的 5 个 `.cpp` 复制到同一个文件夹
3. 把 `main.cpp` 改名成 `esp32_sensorhub.ino`
4. 开发板选 ESP32 Dev Module，选对 COM 口，上传

### 3.3 看串口输出（判断成功与否）

PlatformIO 底部点 **插头图标（Serial Monitor）**，波特率 115200。看到这个就成功了：

```
[I2C] 扫描总线...
  0x23        ← BH1750 光照
  0x38        ← AHT20 温湿度
  0x76        ← BMP280 气压
[SENSOR] AHT20  : OK
[SENSOR] BMP280 : OK
[SENSOR] BH1750 : OK
[BLE] GATT 服务已启动，广播名：SensorHub-01
[DATA] T=26.5C H=50.3% P=1013.2hPa L=320 flags=0x07
[DATA] T=26.6C H=50.1% P=1013.2hPa L=318 flags=0x07
```

**`[DATA]` 每秒刷一行 = 硬件这一步成功** ✅

### 3.4 硬件卡住了怎么办

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 串口一片空白 | 波特率不对 / 线不能传数据 | 改成 115200；换线 |
| 一个设备都没找到 | 线没接好或接反 | 先只接 **一个** AHT20 再扫，确认后再加 |
| 只找到 0x23，没有 0x38 | AHT20 没接好或坏了 | 检查 VCC 是不是接的 3V3 |
| 找到 0x77 不是 0x76 | BMP280 的 SDO 脚电平不同 | 正常，代码里写了两个地址都试 |
| 上传失败 `Failed to connect` | ESP32 没进下载模式 | 按住板子上的 **BOOT** 键再点上传，出现进度后松手 |
| 一直重启 | 供电不足 | 别用电脑前置 USB 口，换后置口或充电头 |

## 四、第三步：合体（手机连上板子）

1. 手机 App → **设置** → **关掉**「模拟数据源」
2. 回到 **设备** 页 → 点「开始扫描」
3. 列表里出现 **SensorHub-01**（真板子，MAC 是真实地址不是 AA:BB:CC）
4. 点进去 → 点「连接」
5. 状态文字依次变成：`正在连接` → `正在发现服务…` → `已就绪`，**小圆点变绿**
6. 四个数字开始跳，曲线开始滚

**状态变绿、数字在跳 = 全流程打通** ✅

### 然后可以玩这些（录屏素材）

- 拖动 **LED 滑杆** → 面包板上的 LED 亮度跟着变
- 点 **鸣叫** → 蜂鸣器响一声
- 手捏住 AHT20 → 温度上升 → 超过 30℃ → 手机状态栏弹出**告警通知**
- 拔掉 ESP32 电源 → App 显示"重连中（第 1 次）"→ 隔几秒重试 → 插回去 → 自动重连成功
- 切到 **历史** 页 → 所有采集记录都在

### 连不上怎么办

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 扫描列表是空的 | 没给权限 / 蓝牙没开 | 手机开蓝牙；App 第一次扫描会弹权限，点"允许" |
| 扫到但连不上，报 133 | 上次连接没释放干净 | 手机**关掉蓝牙再打开**，重进 App |
| 连上了但没数据 | 没订阅上 | 板子按一下复位键（RST/EN），重连 |
| 一直"正在发现服务" | 服务没起来 | 串口看有没有 `[BLE] GATT 服务已启动` |
| 手机太老（Android 7 以下） | minSdk 是 26 | 换一部 Android 8.0 以上的手机 |

## 五、日常改代码的流程

改了 Kotlin 代码后：点 **Run ▶** → App 自动重新装到手机。
改了固件后：点 **Upload →** → 自动烧到板子。

**两边可以分开改，互不影响。** 唯一要注意的是：协议改了（帧格式、UUID）必须**两边一起改**，否则对不上。

### 想改东西，改哪个文件？

| 你想改什么 | 改这个文件 |
|---|---|
| 传感器采样周期默认值 | `firmware/include/config.h` 的 `PERIOD_DEFAULT_MS` |
| 引脚号接错了 | `firmware/include/config.h` 的 `PIN_*` |
| 蓝牙广播名 | `firmware/include/config.h` 的 `DEVICE_NAME` |
| 告警阈值 | App 的「规则」页直接改，或 `AppDatabase.kt` 里的 `seedDefaultRules()` |
| 曲线颜色 | `android/.../res/values/colors.xml` 的 `chart_temp` 等 |
| 界面文字 | `android/.../res/values/strings.xml` |
| 界面布局 | `android/.../res/layout/fragment_*.xml` |
| 卡尔曼滤波参数 | `android/.../domain/Filter.kt` 的 `processNoise` / `measurementNoise` |
| App 包名 | `app/build.gradle.kts` 的 `namespace` 和 `applicationId` |

## 七、如果只想先看到效果（最省事路线）

**不想装 Android Studio？** 那也行，但只能先做硬件部分：

1. 接线 → 烧固件 → 串口看到 `[DATA]` 在刷
2. 手机装一个 **nRF Connect**（应用商店搜），打开就能扫到 SensorHub-01，连上能看到 UUID 和实时数据
3. 这样你能先确认硬件没问题，再回来折腾 Android Studio

> 但最后作业要交的是你自己的 App，所以 Android Studio 迟早要装。
